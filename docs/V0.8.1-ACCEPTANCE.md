## 已完成的工程改进

- 将 `package.json` 中的 `latest` 依赖改为明确版本，减少依赖在不同时间解析到不同版本的风险。
- 扩展 `scripts/check-deploy.mjs`，自动扫描所有 `src` 源码中的相对导入，不再依赖手工维护的组件列表。
- 增加版本格式、锁文件状态与本地存储键唯一性检查。
- README 补充 npm registry 网络故障、锁文件生成及 CI 构建验证说明。

## 手工验收步骤

1. 使用 Node.js 22，在项目根目录运行 `npm install`。
2. 确认生成 `package-lock.json`，将它与代码一起提交。
3. 运行 `npm run check:deploy`，确认静态预检查全部通过；如有相对导入失败，先修复源文件路径。
4. 运行 `npm run build`，确认 `tsc -b` 与 `vite build` 均以退出码 0 结束。
5. 运行 `npm run dev`，分别检查情绪日记、价值观罗盘、成长实验和自我认知的新增、刷新恢复、导出与删除。
6. 在 Netlify 上执行正式构建后，检查浏览器 Console 与 Network，确认静态资源没有 404。
