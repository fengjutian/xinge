# 心格产品路线图与功能规划

- 文档版本：1.0
- 对应产品版本：V0.9.0
- 更新日期：2026-10-30
- 产品定位：面向普通个人用户的心理学互动探索与自我反思工具；先做好核心交互和个人数据控制，暂不接入 AI。

## 1. 产品愿景

心格帮助用户把真实生活中的情境、想法、情绪、身体感受、需要和行动放在一起观察。产品提供的是提问框架、心理学知识与反思工具，而不是人格定型、心理诊断或对未来的预测。

### 设计原则

1. **理解先于判断**：不以单次反应给用户贴标签。
2. **科学但不武断**：区分研究证据、解释框架和个人体验；标明概念的适用边界。
3. **轻量可持续**：一次只做一个小练习，避免把自我探索变成新的绩效任务。
4. **本地优先**：敏感的个人记录默认只留在当前浏览器；导出、删除与数据用途应明确。
5. **用户有决定权**：不强制连续打卡，不用羞耻或焦虑推动留存。
6. **非临床定位**：不诊断、不替代心理治疗；如内容涉及持续且显著的痛苦，提示用户考虑专业支持。

## 2. 目标用户与范围

### 首要用户

希望理解情绪、思维习惯、人际互动和个人成长的普通个人用户；不要求心理学专业背景。

### V0.5 目标

- 让用户可以建立多条情绪日记，而非只有一条覆盖式反思。
- 通过日期、情绪、主题标签和关键词回看记录。
- 提供近七日记录概览，帮助用户描述自己的记录情况。
- 展示个人记录中的标签频次，形成可点击的主题线索。
- 保留原有心理机制练习、概念地图、今日一问、研究笔记和旧反思备份能力。
- 将产品路线、功能规格、隐私原则与验收标准写入工程 ZIP。

### 当前不做

- 不接入 AI 对话或把用户的私密日记发送到外部服务。
- 不建立账号系统、云端同步或服务器数据库。
- 不把情绪强度、记录频率或标签关联转化为临床结论。
- 不做心理疾病筛查、风险评分、人格定型或自动化诊断。
- 不引入 SQLite/WASM + OPFS，直到生产构建和浏览器兼容性经过验证。

## 3. 信息架构

当前导航以轻量的页面锚点组成：

1. **探索地图**：心理概念与探索入口。
2. **今日一问**：用一个具体情境开始反思。
3. **情绪日记**：记录感受、强度、情境、身体感受、需要与标签；查看周度概览和历史记录。
4. **心理机制实验室**：把事件、解释和在意的需要拆开观察。
5. **自我认知**：区分自我评价、对他人看法的猜测、可观察事实与替代解释。
6. **研究笔记**：浏览心理学概念和研究相关内容。

后续正式信息架构方向：

- 探索首页
- 认识自己（价值观、优势、身份叙事、自我认知差距）
- 理解心理（心理机制实验、认知偏差、注意力、记忆与决策）
- 理解关系（关系地图、沟通、边界、冲突复盘）
- 实践与成长（成长实验、习惯观察、阶段回顾）
- 知识与研究（知识依赖网络、参考来源、证据等级与争议）

## 4. V0.5 功能规格

### 4.1 情绪日记

每条记录包含：

- `id`：记录唯一标识。
- `date`：用户选择的日期。
- `emotion`：从一组常见情绪词中选择一个，允许以后扩展自定义词汇。
- `intensity`：1–5 的主观强度，仅用于个人描述。
- `trigger`：当时发生的情境，鼓励描述可观察事实。
- `body`：身体感受或身体状态。
- `need`：当下可能需要的支持、休息、信息、边界等。
- `tags`：零到多个主题标签。

用户故事：作为用户，我希望快速记录某一时刻的感受，以便稍后回看当时的情境，而不是依靠记忆重构。

验收标准：

- 必须至少填写情境、身体感受、需要三项中的一项才能保存。
- 保存成功后列表即时更新，并给出状态提示。
- 默认写入独立的浏览器 `localStorage` 键，不覆盖旧版反思练习数据。
- 存储失败时显示错误提示，不假装保存成功。
- 可以逐条删除；删除前二次确认。
- 可以导出 JSON 备份。

### 4.2 搜索与筛选

- 关键词搜索覆盖情绪、情境、身体感受、需要和标签。
- 支持按情绪或主题标签筛选。
- 筛选标签可从记录卡片与关联线索中点击触发。
- 空结果应提供说明，不显示错误的“无记录”状态。

### 4.3 七日回顾

- 展示最近七天的记录数量柱状图。
- 展示七日记录数、记录中的平均主观强度和情绪种类数。
- 不存在的记录显示为空数据，不补造数值。
- 图表的柱高表达记录数量，而不是心理健康程度。
- 明确说明记录频率与平均强度不构成诊断或因果证据。

### 4.4 反思关联线索

- 以标签频次显示用户记录过的主题。
- 点击标签可筛选历史记录。
- 当前只是主题频次与检索入口，不是统计相关性或心理因果网络。
- 后续若要做真正的反思关联网络，应先定义边的来源（用户主动关联、共同出现、时间顺序等）并在 UI 中明确说明。

### 4.5 数据可控性

- 情绪日记与原有反思练习采用不同的存储键，互不覆盖。
- 情绪日记可导出 JSON。
- 逐条删除前确认。
- 未来全量删除需明确列出会清除的所有本地数据类别，并在执行前确认。
- 浏览器站点数据被清理、使用无痕模式或更换设备时，本地记录可能无法恢复；提示用户保管备份。

## 5. V0.6 已新增：价值观罗盘

- 从 16 项价值方向中选择最多 5 项，并使用上移/下移控制优先顺序。
- 通过开放式问题记录价值的个人意义、近期实践与未来一周的小行动。
- 独立使用 `xinge-value-compass-v1` 本地存储键；支持 JSON 导出和确认后清除。
- 不输出人格标签、分数或标准答案。此练习是反思工具，不是标准化心理测验。

### V0.8 已新增：自我认知反思

- 分开记录具体情境、自我评价、对他人看法的猜测、事实线索、替代解释与下一步行动。
- 支持多条记录、历史回看、逐条删除与 JSON 导出，使用独立本地存储键 `xinge-self-awareness-v1`。
- 不把猜测当作他人真实想法，不使用固定人格标签或自动心理推断。

### V0.9 已新增：心理学知识依赖网络
- 以六个入门节点展示观察、解释、情绪、需要、行动与证据素养之间的学习关系。
- 每个节点展示前置知识、来源类型、适用范围、局限、个人练习和参考来源。
- 支持搜索、分类筛选、节点选择与前置知识跳转。
- 明确区分学习关系与心理因果；网络不是完整学科分类，也不是统一证据等级。

### 后续：理解自己与心理机制
- 心理机制实验室扩充：注意力、记忆、认知偏差、决策和不确定感实验。
- 将知识节点与边抽离为可版本化的数据文件，增加来源更新日期、研究对象、方法、局限和审核状态。
- 研究笔记补充参考文献、证据类型与局限说明。

### V0.7 已新增：个人成长实验

- 每条实验记录包含名称、假设、具体行动、起止日期、状态、观察结果和复盘。
- 支持创建、编辑、逐条删除、清空确认与 JSON 导出。
- 使用独立 `xinge-growth-experiments-v1` 本地存储键，不覆盖其他模块数据。
- 强调个人观察不等于因果证明，不提供人格或心理诊断。

### 后续：个人成长与时间维度

- 人生时间线与重要事件回顾（用户自愿添加）。
- 月度或阶段性回顾，强调描述而非评判。
- 个性化探索路线，基于用户主动选择，不从敏感数据推断用户身份。
- 账号同步只在明确需求和隐私方案确定后评估。

### V1.x：可选 AI 反思伙伴（尚未承诺实现）

- 用户主动选择某条记录并明确同意后，才可将内容提交给模型。
- 发送前展示将提交的字段，支持编辑与取消。
- 优先提供开放式追问、事实与解释区分、不同视角总结。
- 不做诊断、治疗建议或确定性人格推断。
- 说明模型可能出错；提供不使用 AI 的完整替代路径。
- 评估数据保留、供应商政策、密钥管理、费用、滥用防护和适用法规后再实施。

## 6. 技术路线

当前：React 18 + TypeScript + Vite + CSS；浏览器 `localStorage`；Netlify 静态部署。V0.6 增加价值观罗盘，V0.7 增加成长实验，V0.8 增加自我认知反思；各模块使用独立存储键。

数据层边界：

- 现有 `ReflectionStorage` 管理旧版单条反思练习。
- 情绪日记目前使用独立键 `xinge-emotion-journal-v1`。
- 下一步可将情绪日记抽成独立 `EmotionStorage` 接口，并为本地存储适配器编写测试。
- 先完成依赖安装、TypeScript 编译、Vite 生产构建和真实浏览器测试，再评估 SQLite/WASM + OPFS。
- Netlify Functions 临时文件系统不应当作持久数据库。

## 7. 隐私与内容安全

- 默认本地存储，不向服务器上传日记。
- 不收集与核心体验无关的敏感信息。
- 不把记录趋势解释为疾病、人格或心理因果。
- 不用“你一定是……”的确定性语气；优先使用“可能”“可以观察”“目前记录显示”。
- 所有个人数据的导出、删除与未来同步行为必须可理解、可控制。
- 不把心理学教育工具包装成专业诊疗服务。
